Resumen Técnico para NotebookLM: Arquitectura SaaS Laboratorio Clínico
Contexto y Objetivo del Proyecto Origen: Sistema monousuario heredado (creado originalmente en entorno compatible con Microsoft Access / SQL local) para laboratorios clínicos. Propósito: Reconfigurar y modernizar el software para transformarlo en una plataforma SaaS (Software as a Service) moderna, multi-tenant (multi-laboratorio), multiusuario y multimoneda.
Stack Tecnológico Sugerido Base de Datos: PostgreSQL. Estrategia Multi-Tenant: Uso de Row-Level Security (RLS) en PostgreSQL con una columna tenant_id (o laboratorio_id) en tablas maestras y transaccionales para garantizar aislamiento seguro sin duplicar esquemas. Concurrencia: Optimización mediante operaciones asíncronas y consultas cortas/atómicas para evitar bloqueos (row locks) en picos de alta actividad en el laboratorio. Backend: FastAPI (Python). Seleccionado por su alto rendimiento asincrónico (async/await), tipado estricto con Pydantic (vital para datos médicos y financieros) y generación automática de documentación de APIs. Frontend: React + Vite + Tailwind CSS. Manejo de Estado/Caché: Uso propuesto de TanStack Query (React Query) para optimizar llamadas al servidor y caché en cliente.
Módulos Financieros y Estructurales Clave Multimoneda: Incorporación de tablas de tasas de cambio y conversión, almacenando los valores originales de la transacción y una referencia unificada para consolidación contable. Estructura de Datos Base (Migración): Conservación de la lógica de entidades del dominio médico original (Pacientes, Órdenes, Análisis, Costos, Detalles, Tipos de Tarifa, Abonos, Doctores y Empresas) adaptándola a llaves foráneas explícitas y restricciones de integridad en PostgreSQL.
