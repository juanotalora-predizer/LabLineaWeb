SaaS Paquetes de Examenes
¡El concepto es absolutamente claro y constituye una estrategia comercial y de mercadeo fundamental para cualquier laboratorio clínico moderno!
Permitir la creación de Combos o Perfiles de Exámenes (como "Perfil Ejecutivo", "Exámenes de Ingreso Laboral", "Perfil Lipídico Completo") con un precio globalizado y diferencial, acompañado de un análisis comparativo inmediato frente a la suma de los precios individuales, aporta un valor gigante tanto para el laboratorio como para el paciente o la empresa contratante.
¿Cómo se estructura esto técnicamente en nuestra base de datos y en el flujo del POS?
Para soportar esta funcionalidad manteniendo la integridad financiera, la auditoría y la congelación histórica de precios que ya diseñamos, incorporaremos las siguientes tablas al modelo SaaS Multi-Tenant en PostgreSQL:
-- 1. Cabecera del Combo / Perfil de Exámenes CREATE TABLE saas_combos ( consecutivo SERIAL PRIMARY KEY, tenant_id VARCHAR(50) NOT NULL, codigo_combo VARCHAR(30) NOT NULL, nombre_combo VARCHAR(100) NOT NULL, -- Ej: "Perfil Ejecutivo Anual" o "Exámenes Ingreso Laboral" descripcion TEXT, activo BOOLEAN DEFAULT TRUE, CONSTRAINT uk_tenant_combo UNIQUE (tenant_id, codigo_combo) );
-- 2. Precio Globalizado del Combo por Tipo de Tarifa y Moneda CREATE TABLE saas_combos_precio ( consecutivo SERIAL PRIMARY KEY, tenant_id VARCHAR(50) NOT NULL, combo_id INTEGER NOT NULL, tipo_tarifa VARCHAR(15) NOT NULL, -- Referencia a tipo_tarifa(codigo) moneda_codigo VARCHAR(3) NOT NULL DEFAULT 'COP', precio_global NUMERIC(12,2) NOT NULL, -- Precio especial del paquete completo CONSTRAINT fk_cp_combo FOREIGN KEY (combo_id) REFERENCES saas_combos(consecutivo) ON DELETE CASCADE, CONSTRAINT uk_combo_tarifa UNIQUE (tenant_id, combo_id, tipo_tarifa) );
-- 3. Detalle: Qué Exámenes componen el Combo CREATE TABLE saas_combos_detalle ( consecutivo SERIAL PRIMARY KEY, combo_id INTEGER NOT NULL, analisis_id INTEGER NOT NULL, -- Referencia a analisis(consecutivo) cantidad SMALLINT DEFAULT 1 NOT NULL, CONSTRAINT fk_cd_combo FOREIGN KEY (combo_id) REFERENCES saas_combos(consecutivo) ON DELETE CASCADE, CONSTRAINT fk_cd_analisis FOREIGN KEY (analisis_id) REFERENCES analisis(consecutivo) ON DELETE CASCADE );
Lógica de Negocio y Experiencia en el POS (React + FastAPI)
Cuando el recepcionista está en la interfaz del POS creando una orden, el sistema operará de la siguiente manera al seleccionar un Combo:
Selección del Combo: El usuario selecciona el combo (ej. Perfil Ejecutivo) y el tipo de tarifa del paciente.
Cálculo Comparativo Automático (Backend FastAPI): ⚬ El sistema busca todos los exámenes que componen el combo en saas_combos_detalle. ⚬ Consulta el precio individual de cada examen en esa misma tarifa (costo_analisis). ⚬ Suma los valores individuales para obtener el precio total por separado. ⚬ Compara el resultado con el precio_global configurado en saas_combos_precio.
Respuesta Visual en el Panel de React: La interfaz mostrará de inmediato una tarjeta informativa en tiempo real para el operador (y para el cliente si desea ver el beneficio): ⚬ Suma de exámenes individuales: $250.000 COP ⚬ Precio Especial del Combo: $180.000 COP
  ⚬ Ahorro / Variación para el cliente: -$70.000 COP (28% de descuento aplicado por paquete).
Congelamiento Histórico en la Orden: Al pasar la orden a estado PRE_CERRADA (el candado antifraude que definimos antes), el sistema distribuye proporcionalmente o registra el combo desglosado en la orden, asegurando que los valores históricos queden grabados de forma inmutable para la trazabilidad contable y el cálculo de la rentabilidad por examen que realiza el Dashboard.
