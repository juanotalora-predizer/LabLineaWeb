SaaS inventrarios y Costeo
Para cerrar el ciclo financiero, operativo y de costos del SaaS de laboratorios, la incorporación de un Módulo de Inventarios y Proveedores y un Módulo de Nómina Ligero orientado a Costos por Actividad es una decisión maestra.
Esto permitirá que el sistema calcule el costo real por examen (Activity-Based Costing) de forma automatizada, integrando no solo los reactivos y materiales directos, sino también la depreciación/mantenimiento de equipos y el costo de la hora-hombre del personal técnico y bacteriólogos.
A continuación, estructuramos el diseño DDL en PostgreSQL y la lógica de estos dos nuevos módulos vitales:
Módulo de Inventarios, Insumos y Equipos con Mantenimiento
Este módulo diferenciará tres tipos de recursos: Reactivos (asociados directamente a los exámenes), Materiales/Consumibles (gasas, jeringas, tubos de ensayo) y Equipos Biomédicos/Dispositivos (con control de depreciación, horas de operación y mantenimiento).
-- Proveedores del Laboratorio (Multi-Tenant) CREATE TABLE saas_proveedores ( consecutivo SERIAL PRIMARY KEY, tenant_id VARCHAR(50) NOT NULL, nit VARCHAR(50) NOT NULL, nombre VARCHAR(100) NOT NULL, contacto VARCHAR(50), telefono VARCHAR(30), email VARCHAR(100), CONSTRAINT uk_tenant_proveedor UNIQUE (tenant_id, nit) );
-- Catálogo Maestro de Inventario (Reactivos, Materiales y Equipos) CREATE TABLE saas_inventario_items ( consecutivo SERIAL PRIMARY KEY, tenant_id VARCHAR(50) NOT NULL, codigo VARCHAR(30) NOT NULL, nombre VARCHAR(100) NOT NULL, tipo_item VARCHAR(20) NOT NULL, -- 'REACTIVO', 'CONSUMIBLE', 'EQUIPO' unidad_medida VARCHAR(20) NOT NULL, -- 'ML', 'UNIDAD', 'KIT', 'GRAMOS' stock_actual NUMERIC(10,2) DEFAULT 0.00, stock_minimo NUMERIC(10,2) DEFAULT 0.00, costo_promedio_unitario NUMERIC(12,2) DEFAULT 0.00, -- Actualizado por compras proveedor_id INTEGER, CONSTRAINT fk_inv_proveedor FOREIGN KEY (proveedor_id) REFERENCES saas_proveedores(consecutivo), CONSTRAINT uk_tenant_item UNIQUE (tenant_id, codigo) );
-- Registro de Compras de Inventario (Entradas a Almacén) CREATE TABLE saas_compras_inventario ( consecutivo SERIAL PRIMARY KEY, tenant_id VARCHAR(50) NOT NULL, proveedor_id INTEGER NOT NULL, numero_factura_proveedor VARCHAR(50) NOT NULL, fecha_compra TIMESTAMP DEFAULT CURRENT_TIMESTAMP, valor_total_compra NUMERIC(12,2) NOT NULL, usuario_registro VARCHAR(50) NOT NULL, CONSTRAINT fk_compra_prov FOREIGN KEY (proveedor_id) REFERENCES saas_proveedores(consecutivo) );
CREATE TABLE saas_compras_detalle ( consecutivo SERIAL PRIMARY KEY, compra_id INTEGER NOT NULL, item_id INTEGER NOT NULL, cantidad NUMERIC(10,2) NOT NULL, costo_unitario_compra NUMERIC(12,2) NOT NULL, CONSTRAINT fk_det_compra FOREIGN KEY (compra_id) REFERENCES saas_compras_inventario(consecutivo) ON DELETE CASCADE, CONSTRAINT fk_det_item FOREIGN KEY (item_id) REFERENCES saas_inventario_items(consecutivo) );
-- Hoja de Mantenimiento y Control de Actividad para Equipos Biomédicos CREATE TABLE saas_equipos_mantenimiento ( consecutivo SERIAL PRIMARY KEY, tenant_id VARCHAR(50) NOT NULL, item_inventario_id INTEGER NOT NULL, -- Debe ser un item tipo 'EQUIPO' codigo_activo_fijo VARCHAR(50), horas_actividad_mes NUMERIC(8,2) DEFAULT 0.00, -- Horas operativas procesando muestras horas_inactividad_mes NUMERIC(8,2) DEFAULT 0.00, -- Horas en stand-by o mantenimiento costo_hora_operacion NUMERIC(10,2) DEFAULT 0.00, -- Depreciación + Mantenimiento prorrateado fecha_ultimo_mantenimiento DATE, fecha_proximo_mantenimiento DATE, observaciones_mantenimiento TEXT, CONSTRAINT fk_eq_item FOREIGN KEY (item_inventario_id) REFERENCES saas_inventario_items(consecutivo) ON DELETE CASCADE );
Módulo de Nómina Ligero y Asignación de Costos por Hora-Hombre
Para lograr que el sistema distribuya inteligentemente el costo del talento humano (bacteriólogos, auxiliares, recepcionistas) hacia las sedes, las secciones y los exámenes procesados, estructuraremos la nómina de la siguiente manera:
-- Registro del Personal del Laboratorio CREATE TABLE saas_personal ( consecutivo SERIAL PRIMARY KEY, tenant_id VARCHAR(50) NOT NULL, codigo_sede VARCHAR(2) NOT NULL, -- Sede principal de operación identificacion VARCHAR(30) NOT NULL, nombres VARCHAR(50) NOT NULL, apellidos VARCHAR(50) NOT NULL, cargo VARCHAR(50) NOT NULL, -- 'BACTERIOLOGO', 'AUXILIAR_LAB', 'RECEPCIONISTA' salario_mensual_base NUMERIC(12,2) NOT NULL, prestaciones_sociales_estimadas NUMERIC(12,2) DEFAULT 0.00, -- Cargas prestacionales o seguridad social horas_laborales_mes_estandar SMALLINT DEFAULT 160, -- Ej: 160 horas al mes activo BOOLEAN DEFAULT TRUE, CONSTRAINT uk_tenant_personal UNIQUE (tenant_id, identificacion), CONSTRAINT fk_personal_sede FOREIGN KEY (tenant_id, codigo_sede) REFERENCES sedes(tenant_id, codigo_sede) ON UPDATE CASCADE );
-- Distribución de Tiempos o Asignación a Secciones (Para prorrateo de costos) CREATE TABLE saas_personal_asignacion_seccion ( consecutivo SERIAL PRIMARY KEY, personal_id INTEGER NOT NULL, seccion_codigo VARCHAR(50) NOT NULL, tenant_id VARCHAR(50) NOT NULL, porcentaje_dedicacion NUMERIC(5,2) DEFAULT 100.00, -- Porcentaje de su tiempo en esta sección CONSTRAINT fk_pas_personal FOREIGN KEY (personal_id) REFERENCES saas_personal(consecutivo) ON DELETE CASCADE, CONSTRAINT fk_pas_seccion FOREIGN KEY (tenant_id, seccion_codigo) REFERENCES seccion(tenant_id, codigo) ON UPDATE CASCADE );
¿Cómo se conectan Inventarios y Nómina para calcular el Costo Real por Examen?
Con estas tablas, el motor analítico del SaaS en FastAPI podrá realizar un cálculo de costos por actividad sumamente preciso y automatizado:
Costo de Reactivos y Materiales Directos: ⚬ Cuando se crea la orden y se procesa un examen (ej. Hemograma), el sistema consulta la tabla costo_insumos_analisis y descuenta automáticamente del inventario la cantidad exacta de reactivo (ej. 0.05 ml de colorante) y material (ej. 1 jeringa, 1 tubo lila). El costo de estos insumos se suma directamente al costo del examen.
Costo de Operación de Equipos (Prorrata): ⚬ Tomando las horas_actividad_mes y el costo_hora_operacion registrado en la hoja de mantenimiento de los analizadores de laboratorio, el sistema prorratea el costo por minuto de uso del equipo y lo asigna al examen procesado.
Costo de Mano de Obra (Hora-Hombre): ⚬ El sistema calcula el costo por hora de cada bacteriólogo basándose en su salario_mensual_base dividido entre las horas_laborales_mes_estandar. Cruzando esto con el tiempo estimado que toma procesar un examen en una sección específica, se asigna el costo de personal correspondiente.
Impacto en el Dashboard Gerencial (Rentabilidad Real)
Gracias a este módulo integrado, el Dashboard que visualiza el laboratorio mostrará métricas financieras de grado industrial:
⚬ Margen de Utilidad Neta Real por Examen: Ingresos (Tarifa cobrada) menos (-) Costo de Reactivos y Materiales menos (-) Costo de Uso de Equipos menos (-) Costo de Mano de Obra (Nómina). ⚬ Sección Más Costosa vs. Sección Más Rentable: Identifica qué área del laboratorio absorbe más presupuesto en personal e insumos y si su volumen de facturación justifica dichos costos operativos.
